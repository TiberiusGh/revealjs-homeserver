RESTLess

Enhancing State-of-the-Art REST API Fuzzing with LLMs in Cloud Service Computing

Tao Zheng, Jiang Shao, Jinqiao Dai, Shuyu Jiang, Xingshu Chen, Changxiang Shen

Sichuan University • IEEE Transactions on Services Computing, 2024

The Problem

REST APIs are critical infrastructure for cloud services (Microsoft Azure, AWS, Google Cloud), but detecting vulnerabilities is challenging.

Current Fuzzer Limitations

  • Low pass rates through cloud gateway semantic checks
  • Short test sequences miss deep bugs
  • Dictionary-based rendering lacks semantic value

Consequences

  • Inefficient fuzzing performance
  • Unable to trigger hard-to-reach states
  • Missing vulnerabilities in complex API combinations

Key Observations

Observation 1: Inefficient Fuzzing

  • Test sequences struggle to pass semantic checks
  • High failure rates from invalid parameter values
  • Low code coverage across cloud services

Observation 2: Insufficient Expansion

  • Sequences are typically short (avg ~1.2-2.7 operations)
  • All parameters rendered simultaneously
  • Single type of test sequences generated

Root Cause: Semantic quality of parameters + lack of weight-based rendering strategies

RESTLess: The Solution

A flexible and efficient approach with hybrid optimization strategies

Prompt Engineering Strategy

Given parameter A with value B:

  1. Learn the semantics of parameter value B
  2. Generate 5 new values for A matching those semantics
  3. Output as a list (boolean types get only 2 values)

Result: RTSet dataset with 62,250 parameter name-value pairs

Weight-Based Render Order Optimization

Parameter Weights

  • High weight: Required parameters (essential for valid requests)
  • Low weight: Non-required parameters (can cause failures if incorrect)

Algorithm

  1. Render all required parameters first → S₁
  2. Execute initial sequence
  3. Add non-required params with probability ω (default 80%)
  4. Repeat until all parameters rendered

Formula: Sᵢ = S₁ ∪ Σ(ω · bᵢ) for non-required parameters bᵢ

Ablation Study (RQ4)

Semantic-Only

  • Highest contribution to operation coverage
  • More valid sequences → higher bug discovery probability

Render-Only

  • Highest contribution to bug detection
  • More diverse and longer sequences
  • Reduced parameter rendering errors

Combined (RESTLess): Best overall performance across all metrics, demonstrating synergy between both modules

RTSet: The Parameter Dataset

  • Source: 286 OpenAPI specifications from API.guru (2018-2023)
  • Size: 62,250 parameter name-value pairs
  • Augmentation: ChatGPT-generated semantically similar values

Trends Observed in Cloud API Evolution

  • 📈 Increasing number of API parameters
  • 📝 More noun/verb attributes in parameter names
  • 🔤 Higher proportion of string/integer types
  • 📏 Growing byte length of parameter values

Key Contributions

1. RTSet Dataset

Comprehensive dataset of 62,250 REST API valid parameters for semantic enhancement

2. Render Order Optimization

Flexible algorithm that increases sequence length and diversity based on parameter weights

3. Empirical Validation

38 real vulnerabilities found, 16 confirmed and fixed by major cloud vendors

Conclusion

RESTLess addresses the fundamental limitations of REST API fuzzers through:

  • LLM-powered semantic enhancement for better gateway compliance
  • Weight-based rendering optimization for longer, diverse sequences
